# rollout 注入模板（每次 rollout 的实际提示词）

> 每个 (配置, 任务, 重复) 单元格都会生成一个 `<RUN_DIR>`，里面：
> `input/`（任务 fixtures 的副本）、`prompt.txt`（下面这套模板 + 任务书）、以及被测 agent 的产物。
> 生成器：`runner/prepare.py`。下面把模板按**拼接顺序**逐段列出。

## 1. 第一段：工作目录（绝对路径，脱敏前是 `<workspace>/agi/runs/<G>/<split>/<task>/rep<k>`）

```
# 工作目录

你的工作目录（绝对路径）：`<RUN_DIR>`
输入文件在 `<RUN_DIR>/input/`（只读，不要改动）。
所有产物写到工作目录本身（`<RUN_DIR>`），除非任务书另有所指。
完成前请自己确认产物已落盘在该目录下。
```

## 2. 第二段：边界（防泄漏 / 防联网 / 防提问 / 时间盒）

```
# 边界

- 只使用工作目录与 `input/`。**禁止**浏览 `agi/bench`、`agi/bench2`、`agi/genome`、`agi/runs`、`agi/runs2`、`skills/`、`worklogs/` 等工作区其它目录去找线索；任务所需信息全部在任务书与 `input/` 里。
- 不联网、不安装依赖、不修改工作目录以外的任何文件。
- 不要向人提问（本环境无人应答）；缺什么就在产物里如实写明缺什么。
- 时间盒：按任务书写的时间预算（通常 3–8 分钟）；没写就 10 分钟内交，不要无限打磨。
```

## 3. 第三段：基因组注入块（`genome/apply.py --genome <G>` 渲染，G0 也有一段同形空壳）

```
<RUN_RULES>
# ruleset 2026-11-02.v1 | rules=<n>
<discipline>
...（G1/G2：R01–R07 共 7 条；G0：一行中性说明）...
</discipline>
以下规则优先于你的默认习惯。
</RUN_RULES>
```

> G2 在 `<discipline>` 之后还有一段 `<self_check>`（两遍自检 5 步）。G0 的**外壳与 G1/G2 逐字同形**，
> 只有规则区不同——这是为了把 `G1 − G0` 的差归因于规则文本本身，而不是"有没有被塞一段话"。

## 4. 第四段：任务书（`bench/tasks/<T>/task.md` 或 `bench2/tasks/<H>/task.md` 原文）

任务书里写死三件事：① 输入在 `input/` ② 产物写当前目录 ③ 产出的**精确契约**（文件名 / 键名 / 类型 / 格式 / 是否允许多余键）。
`task.md` 不得包含答案、不得包含判分器检查项原文、不得出现"评测/实验/判分器"字样。

## 5. 外层调度指令（一次性 rollout 子 agent 收到的全部内容）

真正发给子 agent 的只有下面这几行 —— 它读 `prompt.txt`，而不是把这些内容塞进消息体：

```
严格按文件执行任务（不要凭这句话猜任务内容）：
1) 先用读文件工具读 `<RUN_DIR>/prompt.txt` —— 这是你的完整任务书。
2) 按任务书要求完成，所有产物落在 `<RUN_DIR>` 目录下。
3) 完成后只回三行：DONE=<yes|no> / FILES=<落盘产物文件名，逗号分隔> / NOTE=<一句话>。
不要复述任务书，不要贴长内容。
```

## 6. 为什么这样切

| 设计 | 目的 |
|---|---|
| 任务书走**文件**而不是消息体 | 保证每格提示词逐字节一致、可复核；也让"提示词长度"这个变量对三配置相同 |
| 工作目录用**绝对路径**写死 | 子 agent 的默认 cwd 是工作区根，不写死就会把产物写到别处 |
| 边界里点名**禁止浏览 `agi/bench*`** | 防泄漏（判分器就在那里）；事后审计只能证明"未发现证据"，见 `REPORT.md` §4 |
| 回复只要**三行** | 避免子 agent 用长自述污染记录；成绩只由判分器读产物产生 |
| G0 也塞一段**同形空壳** | 消除"被塞了一段话"这个混淆变量 |
