# 决策日志（时间序）

## D1 · 把不可证伪的话换成可证伪的问题（22:00）

**决定**：不回应"成为 AGI"，而改为回答"给 agent 加纪律规则/自检过程，能否测出能力增量"。同时明确：本实验不构成任何 AGI 主张。
**理由**：前者无法被实验打脸，任何"做到了"的回答都是不可核对的自我评价。
**代价**：交付物从"更强的我"变成"一份可能为负的报告"。**接受**，并在 `CHARTER.md` §1 写死禁令。

## D2 · 判据本体先于一切（22:02）

**决定**：由 Lead 先写 `bench/CONTRACT.md`（任务轴、split 分配、判分器 CLI、selftest 门禁、控制台编码），实现方只读、发现歧义回给 Lead。
**理由**：判据如果由实现方边做边定，就会出现"为了让门禁变绿而放宽判据"。
**代价**：Lead 先花时间定契约；换来的是 6 个实现方可以真正并行且口径一致。

## D3 · 双向门禁：`good` 必须过、`bad` 必须挂（22:04）

**决定**：每道题除了"正确答案"，还必须交一份"最像样的错误解"，`selftest.py` 同时判两侧。
**理由**：恒真判分器（`return True`）是最常见的自欺形式；只有 bad 必须 FAIL 才能把它抓出来。
**代价**：实现工作量翻倍（每题的 good 相当于"证明这题可解"）。**事后证明值得**：门禁抓出 3 类真实缺陷（进程内调用误判、坏样本是空目录、判分器写 `__pycache__`）。

## D4 · 并行分工按"互不重叠的写入范围"切（22:05）

**决定**：7 个 teammate 各自写入范围互不重叠（`T01..T06` / `T07..T12` / `H01..H03` / `H04..H06` / `genome/` / 两份预注册文档 / `audit/`），Lead 只碰 `runner/` 与判据本体。
**理由**：无 git 环境下并发写同一文件无法回滚（没有 version guard 保护的是 shell/脚本）。
**代价**：`selftest.py` 需要自动发现任务，不能写死任务名（这也是 bench-code 必须改调用方式的原因，见 D5）。

## D5 · 裁决 1：门禁必须走 CLI，不许进程内 import 判分器（22:16）

**冲突**：`selftest.py` 用"import 判分器 + 调 `main(argv)`"的方式跑；而 `bench-disc` 的判分器是独立脚本 `main()`，于是全部被打成 `exit 2 TypeError`。
**决定**：改**门禁**——一律 `subprocess` 调 `python <task>/grade.py --run-dir ... --task-dir ...`，解析 stdout 最后一行 JSON。
**理由**：`CONTRACT.md` §5 规定的唯一调用方式就是 CLI；门禁把合规判分器判成坏的，是门禁缺陷。
**代价**：子进程带超时与编码处理；本机沙箱禁 fd 管道（D8），还得加文件重定向回退。

## D6 · 裁决 2：第二轮 `meta.json` 放宽到 8 键（23:0x）

**冲突**：`bench2/CONTRACT.md` §2 要求 `hardness` 字段，但 `selftest.py` 从第一轮复制，`META_KEYS` 只允许 7 键且做双向校验 ⇒ 只要写 `hardness` 就必 NG。两名实现方同时撞到并上报。
**决定**：改**门禁**（`bench2/selftest.py`：`META_KEYS` 加 `hardness`，`AXES` 注册 6 个新轴），并在 `bench2/CONTRACT.md` §2 补记变更与唯一口径；**第一轮 `bench/` 不动**。
**理由**：契约是判据本体，实现方无权自行放宽；但"探索轮的新字段"是设计变更，应由 Lead 改工具并留痕。
**代价**：`bench/` 与 `bench2/` 的 `selftest.py` 从此不同（`1ad7abfc…` vs `abadf499…`），必须分别引用，不能混用。

## D7 · 管线缺陷：`grade_all.py` 相对路径口径（22:28）

**问题**：首跑第一轮 G0/dev，`run_dir` 被解析成 `agi/runs/G0/dev/agi/runs/G0/dev/T05/rep2`，12 条全判 FAIL。
**决定**：删掉这份 `score.json`；`prepare.py` 改输出**绝对路径** `run_dir`（并保留 `run_dir_rel` 供人读），加 `--manifest-only` 只重写 manifest 不动产物。
**代价**：出现"未申报的重跑"——`PROTOCOL.md` §3.5 要求重跑前先记账。**当时没记**，被独立复核（I9）指出；事后补了 `note` 并明确标注"事后补记、时间戳晚于重跑，不能充当事前申报"。

## D8 · 环境事实：本机沙箱禁 fd 管道（22:20）

**问题**：`subprocess.run(capture_output=True)` 在 `_winapi.CreatePipe` 抛 `PermissionError [WinError 5]`。
**决定**：runner 侧改为**进程内 import** `genome/apply.py` 调 `render()`（`runner/_genome.py`）；判分器批跑走"文件重定向"回退。三个实现方各撞一次，都按纪律没绕沙箱。
**代价**：`apply.py` 必须保持纯函数式（确定性、无副作用），这条被写进 `genome/README.md` 的确定性契约。

## D9 · 第一轮结果全 0：不美化，改问下一个问题（23:01）

**观测**：dev 三配置 10/12、heldout 三配置 6/6，Δ 全 0；dev 唯一失分点 T02 是判分器缺陷（隐藏向量 `svc=Web` 越出题面）。
**决定**：（a）判据本体**不改**（改判据=换实验），T02 只记为缺陷；（b）承认天花板效应，并在 `ROUND1.md` §4 写"底座已被工作区 preset 武装过，G0 不是裸模型"；（c）**另开一轮**（`bench2/`）把难度推到底座会失败的地方，并明文写"第二轮不能支持/推翻第一轮"。
**理由**：在饱和的题上加规则不会有任何新信息；但"更难"是设计直觉，必须实测（结果仍然没打下来，见 `ROUND2.md` §6）。
