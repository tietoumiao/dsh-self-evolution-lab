# 任务：计算作业依赖图的关键路径

`input\jobs.json` 给出一组带依赖的作业。请按下面的规则算出调度表。

## 输入

- `input\jobs.json`，形状：
  ```json
  {"jobs": [{"id": "A", "duration": 3, "deps": []},
            {"id": "B", "duration": 2, "deps": ["A"]}]}
  ```
  - `id`：字符串，全局唯一。
  - `duration`：正整数（分钟）。
  - `deps`：该作业依赖的作业 id 数组，含义是"这些作业做完后才能开始"。
  - 同一个作业可以被多个作业依赖；保证无环、依赖的 id 都存在。

## 产出

在当前目录写一个文件 `schedule.json`（UTF-8，不要 BOM）。

## 契约

顶层键**恰好**是 `makespan`、`total_work`、`order`、`earliest_start`、`critical_path` 五个，数值一律用 JSON 整数，不许写成字符串或浮点数。

- `earliest_start`：对象，键是**每一个**作业 id（一个都不能少，也不能多），值是整数最早开始时刻（分钟）。
  规则：没有依赖的作业为 `0`；其余作业 = 它所有依赖的「最早开始 + 时长」里的最大值。
- `makespan`：整数 = 所有作业「最早开始 + 时长」的最大值。
- `total_work`：整数 = 所有作业 `duration` 之和。
- `order`：数组，拓扑序，用 Kahn 算法从上往下展开：每步在「依赖都已排入」的作业里取 `id` 字典序（ASCII）最小的一个。
  长度等于作业数，每个 id 恰好出现一次。
- `critical_path`：数组，一条从最早作业到最晚作业的链，规则：
  1. 终点：取「最早开始 + 时长」最大的作业；并列时取 `id` 最小者。
  2. 从当前作业往它的依赖走：取「最早开始 + 时长」最大的那个依赖；并列时取 `id` 最小者。
  3. 当前作业没有依赖时停止。
  4. 把回溯得到的链条**反序**输出，即数组第一个元素是最早的那个作业，最后一个是终点。
  链条上相邻两个作业之间必须是真实的依赖关系。

## 自检

交之前必须自己验证：`earliest_start` 的键集与作业 id 集合完全一致；`order` 确实是拓扑序且满足最小 id 规则；`makespan` 等于「终点作业的最早开始 + 时长」；`critical_path` 每一步都是真实依赖、且终点是 makespan 的那个作业。
